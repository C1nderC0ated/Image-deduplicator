# Image Inventorization - package requirements, by stage.
#
# EASIEST: don't use this file. Run the setup helper - it detects your GPU,
# picks the right PyTorch build, shows every command and asks before running:
#     Windows        Check-Image-Tools.bat   (offers setup when something is missing)
#     Linux / macOS  ./imgdedup.sh setup
#
# PREREQUISITES - these are not in the list below, because they are what
# RUNS the list below. Neither is guaranteed to come with Python:
#
#   pip    Packaged separately on most Linux distros. Without it every
#          command here fails with "No module named pip", which looks like
#          a broken toolkit rather than a missing system package.
#            Arch            sudo pacman -S python-pip
#            Debian/Ubuntu   sudo apt install python3-pip
#            Fedora          sudo dnf install python3-pip
#
#   venv   Required, not optional, on Arch, Debian 12+, Ubuntu 23.04+,
#          Fedora 38+ and Homebrew: those mark their Python externally
#          managed (PEP 668) and pip refuses to install into it at all, so
#          a virtual environment is the only route. Debian splits it out:
#            sudo apt install python3-venv
#          Where pip is missing but venv works, a venv supplies its own pip.
#
#   Check both, per interpreter:   ./imgdedup.sh doctor
#
# Minimal (Collect only). Every picture in a scanned folder goes through
# Pillow's decoders, and Pillow 13.0.0 closed 41 advisories that the OSV
# database had open against 12.3.0 on 2026-11-12, a heap overflow in the
# JPEG decoder among them. Nothing was backported and 13 needs Python 3.11,
# so Python 3.9 and 3.10 (both end-of-life) get the newest Pillow they can
# install, which has those open. The toolkit itself runs on 10.0.0 and newer.
pillow>=13.0.0; python_version >= "3.11"
pillow>=11.3.0; python_version < "3.11"

# Analyze stage:
numpy>=1.24.0
# Crop-containment detection in Analyze (the "ncc" tier). Recommended.
# 4.8.1.78 is the first build without the libwebp bug CVE-2023-4863:
opencv-python-headless>=4.8.1.78

# Semantic stage (Embed) - transformers from PyPI, torch installed SEPARATELY
# because the right build depends on your hardware. Pick ONE:
#
#   CPU only (always works):
#     pip install torch --index-url https://download.pytorch.org/whl/cpu
#   NVIDIA GPU (CUDA):
#     pip install torch --index-url https://download.pytorch.org/whl/cu132
#   NVIDIA before Turing (GTX 9xx/10xx, Titan X/Xp/V, Quadro M/P) - CUDA
#   12.8 and newer builds carry no kernels for these cards. cu126 ends at
#   PyTorch 2.14.1, the last release built for them:
#     pip install torch --index-url https://download.pytorch.org/whl/cu126
#   AMD GPU on LINUX (ROCm):
#     pip install torch --index-url https://download.pytorch.org/whl/rocm10.0
#   AMD Vega and Radeon VII on LINUX - PyTorch 2.15 dropped their kernels.
#   rocm7.2 ends at 2.14.1, the last release built for them:
#     pip install torch --index-url https://download.pytorch.org/whl/rocm7.2
#   Intel GPU (XPU):
#     pip install torch --index-url https://download.pytorch.org/whl/xpu
#
#   These version suffixes MOVE - cu128 became cu132, and rocm7.2 became
#   rocm7.14 and rocm10.0. The setup helper reads the current list from
#   download.pytorch.org instead of trusting a number written here, so
#   prefer it over copying these lines. Current PyTorch (2.15) needs Python
#   3.11 or newer; for Python 3.10, cu132, cu126 and rocm7.2 hold 2.14.1.
#
#   AMD GPU on WINDOWS: not from PyPI. The wheels setup installs are AMD's
#   ROCm 7.2.1 set at repo.radeon.com, ONLY for Python 3.12 (they are
#   full-ABI cp312 wheels, so no other Python can load them - this is AMD's
#   build matrix, not a setting). Install Python 3.12 alongside, run setup
#   with it, and point just the Embed stage at it via IMGDEDUP_PYTHON.
#   AMD's newer builds, for more Pythons and from an index of AMD's own,
#   are not installed by setup. See README, "AMD GPUs".
#
#   torchvision is NOT needed by anything here, and a stale one breaks
#   transformers - do not install it "just in case".
#
#   Installed the CPU build by mistake (version shows "+cpu")? Uninstall first:
#     pip uninstall torch
#   then install from the right index - a +cpu wheel can never use a GPU.
#
# 5.10.0 is the first release with no published vulnerability open. It
# needs Python 3.10; on 3.9 the newest transformers is 4.57.6. The current
# release (5.22) accepts torch 2.6 and newer.
transformers>=5.10.0; python_version >= "3.10"
transformers>=4.43.0; python_version < "3.10"
